# v4.11 — Verified Placeholder-First Hero System

## Current missing hero assets
These files are intentionally absent from `/images/`:
- `about-institutional-architecture.jpg`
- `insights-editorial-hero.jpg`
- `gallery-editorial-hero.jpg`

## Required behavior
Each corresponding hero is now explicitly marked with
`data-placeholder-image="true"`.

The rendering state is deterministic:
- If the JPG is already available and loads successfully, the JPG renders.
- If the JPG is unavailable, the hero immediately enters placeholder-pending
  state and the approved placeholder occupies the image area.
- If the image subsequently errors, the existing `.is-empty` fallback takes
  over.
- If the exact JPG is later supplied at the expected path, no HTML change is
  required; a successful image load removes the placeholder state.

## What was actually verified in this build
1. The three expected JPG files are absent.
2. The three HTML hero slots reference those exact filenames.
3. All three slots contain the documented placeholder markup.
4. All three slots carry the explicit placeholder-first marker.
5. The JavaScript has a load-success path and an error/fallback path.
6. CSS explicitly displays the placeholder for the pending state.
7. The loading logo has been reduced to 28px inside a 64px mark.
