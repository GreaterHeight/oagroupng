# v4.14 — Hero Placeholder Contrast QA

## Problem observed
When a missing hero JPG activated the light placeholder, the page-hero
editorial copy retained the white-on-photo treatment. The result was
insufficient contrast and the text appeared lost against the light background.

## Fix
The hero copy now switches to the OA Group dark ink color whenever its hero
image is pending or unavailable.

Two mechanisms are provided:
1. Modern browsers: CSS `:has()` reacts directly to the hero image state.
2. Compatibility fallback: JavaScript mirrors the state to
   `.has-placeholder-image`.

The placeholder itself remains the approved light placeholder, while the
headline, eyebrow and lead copy become dark and readable.

## Expected states
- Real JPG available → white-on-image treatment.
- JPG missing/loading → light placeholder + dark hero copy.
- JPG fails → light placeholder + dark hero copy.
- JPG later supplied → real image automatically restores the image treatment.

## Verification
Static checks passed for CSS state rules, JavaScript state mirroring, and all
page-hero slots in the v4.13 build.
