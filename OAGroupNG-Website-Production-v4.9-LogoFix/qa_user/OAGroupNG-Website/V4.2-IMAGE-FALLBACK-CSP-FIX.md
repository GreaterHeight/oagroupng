# v4.2 — Image Placeholder Fix: CSP-Safe Error Handling

## Root cause

The previous placeholder implementation attached `onerror="..."` directly to
`<img>` elements. The website's Content-Security-Policy explicitly uses
`script-src 'self'`, which blocks inline event-handler attributes such as
`onerror`. Therefore, when a JPG was missing, the browser displayed its native
broken-image icon and alt text instead of executing the placeholder logic.

## Fix

The website no longer depends on inline image event handlers.

`/js/main.js` now installs a **capture-phase `error` listener** for image load
failures. It also performs a post-parse scan of completed images whose
`naturalWidth === 0`, covering eager images that may have failed before the
script's listener was attached.

When a normal editorial image fails:

1. the failed image is removed;
2. `.is-empty` is applied to its `.arch-frame`;
3. the existing `.arch-frame-placeholder` becomes visible.

The same approach is applied to the gallery lightbox's `.modal__media`.

## Important consequence

The website may legitimately contain image paths for assets that have not yet
been generated. That is intentional. Missing assets now produce the designed
placeholder instead of a broken-image icon.

When the correct JPG is later placed in `/images/` using the exact filename
specified by `IMAGE-PROMPTS.md`, the real image displays automatically. No HTML
change is required.
